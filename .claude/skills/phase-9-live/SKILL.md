# /phase-9-live — трафик, рейтинг, требования

## 🧭 Phase state marker (v4.67.1+)

На входе в фазу **обязательно** зафиксируй machine state:

```bash
node .claude/skills/status/references/phase-state.mjs start 9
```

Только после всех штатных gate/проверок и обязательных решений пользователя отметь выход фазы:

```bash
node .claude/skills/status/references/phase-state.mjs complete 9 wiki/metrics.md
```

Marker не заменяет evidence и не разрешает перескочить STOP-point. `/status` использует его как
machine-readable progression state, а сами артефакты остаются доказательством результата.


**Модель:** `sonnet` — события и замеры по расписанию.


1. `/seasonal-event` — календарь событий сейчас + напоминание раз в 2-3 недели.
2. Rating-watch: рейтинг из Консоли → таблица в metrics.md (красная линия 2.13, тревога <40).
3. `/audit-requirements` — ежемесячно или при любом отказе.
4. `/product-metrics` re-review — каждые 30 дней (факт против таргетов).


## 🎛️ AI STUDIO 4.67 — измеряемый creative loop

AI generation после релиза используется только как эксперимент:
1. слабый CTR/creative symptom → сформулировать одну гипотезу;
2. `/prompt-compiler` → `/image-studio` → `art-director`;
3. A/B через платформу, результат записать в `wiki/decisions/`;
4. победивший visual DNA вернуть в style bible, чтобы следующие ассеты учились на факте.

Если меняется gameplay/UX, это не «быстрая AI-правка» — возврат в Ф2/Ф3 и повтор Ф7–Ф8.

## Правила фазы (общие)
- Каждый под-скил сохраняет свои гейты (game-design жёстко стоит без metrics.md и т.д.) — фаза их НЕ обходит.
- Между шагами: короткая сверка «что сделано» фактом (файл/греп), не заявлением.
- В конце фазы: сводка (что создано, что требует твоего решения) + команда СЛЕДУЮЩЕЙ фазы.
- Финал: wiki/_map.md + запись в sessions + node scripts/check-drift.mjs (для движковых правок).

## Следующая фаза: цикл, а не финиш
Ф9 — не конец, а петля: `/phase-9-live` повторяется по расписанию (событие → замер → правка).
Что дальше по фактам:
- рейтинг падает / D7 ниже цели → назад в **`/phase-2-design`** (пересмотр удержания) и
  **`/phase-3-construct`** (реализация), затем снова Ф7-Ф8;
- игра стабильна и метрики держатся → **`/port rustore`** (или vk) — новая аудитория без
  нового контента;
- контент-план исчерпан → **`/phase-1-analyze`** на следующую игру.
Следующая фаза: `/phase-9-live` (по расписанию) либо возврат в Ф2 по вердикту метрик.

## 📊 ПЛАН vs ФАКТ — обязательный замер (иначе следующая игра проектируется так же вслепую)

Через 7 и 30 дней после релиза внеси в `wiki/metrics.md` таблицу:
| Метрика | План (из Ф1) | Факт | Расхождение |
|---|---|---|---|
| D1 / D7 / D30 | | | |
| Средняя сессия | | | |
| RV на DAU | | | |
| Доля вступивших в клан к D7 (если социалка) | | | |

Правила чтения:
- расхождение **>30% в любую сторону** — модель удержания неверна; разбери ПОЧЕМУ и запиши
  вывод в `wiki/decisions/`, иначе следующая игра получит те же выдуманные цели;
- факт лучше плана — тоже разбирай: значит недооценили жанр и можно было делать больше;
- **эти числа становятся ориентиром для Ф1 следующей игры** — они честнее любых отраслевых
  средних, потому что тут твоя аудитория и твой источник трафика.
Без этой таблицы цикл Ф9→Ф1 разорван: конвейер не учится на собственных релизах.

## 📈 CTR и A/B креативов (через 7-14 дней после релиза)
1. Выгрузи `ctr_icon`, `ctr_cover`, `conversion_to_play` (см. /store-creatives).

4. Итог не раньше недели; вывод и победителя запиши в `wiki/decisions/`.
