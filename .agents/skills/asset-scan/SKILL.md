# $asset-scan <папка> — разведать папку с ассетами и завести в библиотеку

Пользователь показывает папку с кучей пакетов (архивы, .unitypackage, распакованные папки).
Задача: понять, что в каждом, и завести в `asset-library.json` с тегами, применимостью и
лицензией. Работает пачками: одна папка за прогон, следующую пользователь даст потом.

## Шаг 1 — Инвентаризация ФАКТАМИ (без интернета)
```
node scripts/asset-scan.mjs "<папка>" --out asset-scan-draft.json
```
Скрипт НЕ распаковывает архивы (только листинг) и даёт по каждому пакету: размер,
гистограмму расширений, образцы путей, предварительный `kind_guess`. Покажи пользователю
таблицу из вывода — это уже полезно само по себе.

## Шаг 1.5 — ПАРАЛЛЕЛЬНЫЙ РЕЖИМ (от ~40 пакетов — обязателен)
Поиск по каждому паку идёт последовательно и на сотнях пакетов занимает часы. Разрежь работу:
```
node scripts/asset-shard.mjs asset-scan-draft.json --shards 10
```
→ `asset-shards/shard-01.json … shard-10.json`. Запусти **по агенту `asset-researcher` на каждый
шард ОДНИМ сообщением** (параллельно, а не по очереди): каждому дай путь к его шарду. Агенты
пишут `shard-NN.done.json` и в общую библиотеку не лезут — гонок за файл нет.

Когда все отчитались:
```
node scripts/asset-merge.mjs           # --dry, чтобы сперва посмотреть сводку
```
Менеджер дедупит по пути, **сохраняет пользовательские rating/verdict**, пишет библиотеку через
data-dir (автобэкап предыдущей версии) и печатает сводку + список неподтверждённых лицензий.
Не отработавший шард виден в выводе как «НЕ готов» — перезапусти агента только на него.

Меньше ~40 пакетов — делай сам последовательно (шаги 2-4), накладные расходы не окупятся.

## Шаг 2 — Уточнение в интернете (только там, где нужно)
Правило экономии: **ищи не про всё подряд**, а только когда имя не говорит само за себя
или неясна лицензия. Для каждого такого пакета один-два поиска: `<имя пака> asset pack`,
при необходимости `<вендор> license`. Что выясняем:
- **вендор и что внутри** (жанр, сеттинг, состав) — идёт в `desc`;
- **лицензия** → `lic`: `free` (CC0/MIT — Kenney, Quaternius), `attr` (CC-BY — многое с
  OpenGameArt/itch), `paid` (куплено — Synty, Unity Asset Store), `no` (NC/GPL — не берём);
- если лицензию установить НЕ удалось — ставь `lic: "no"` и в `verdict` пиши
  «лицензия не подтверждена, проверить у вендора». Гадать в пользу разрешения ЗАПРЕЩЕНО.

## Шаг 3 — Классификация (заполняем поля)
- `kind` — СТРОГО из словаря: `2d` | `3d` | `audio` | `unity` | `font` | `ui`. Придуманные
  значения ломают фильтры; детализация идёт в теги. После слияния прогоняй
  `node scripts/asset-normalize.mjs` — он схлопнет отклонения и сохранит исходное в тегах;
- `use` — **для каких игр**: `2d` / `3d` / `any`. 3D-паки помечай `any` только если реально
  планируем рендер в спрайты, и тогда пиши рецепт в `notes`;
- `tags` — 4-8 штук, СЛОВАМИ ПОИСКА: жанр, сеттинг, объекты («средневековье, замок, оружие,
  пиксель-арт, топ-даун»). Теги — главный канал, по которому Forge потом найдёт пак;
- `notes` — как извлекать и подводные камни (для .unitypackage: не распаковывать целиком,
  Blender для скининга, оптимизация перед укладкой);
- `rating: 0` — оценку ставит пользователь после реального использования, НЕ выдумывай.

## Шаг 3.5 — ДУБЛИ И ВЛОЖЕННОСТЬ (скрипт уже разметил, тебе решать)
Скрипт спускается в папки-контейнеры (папка, внутри которой ≥2 пакета и почти нет своих
ассетов, паком НЕ считается — он идёт внутрь, до 3 уровней) и помечает каждую находку:
- `already_in_library: "exact"` — этот путь уже заведён → **обнови поля, не создавай запись**;
- `already_in_library: "overlap:<путь>"` — пересечение по вложенности (раньше завели родителя,
  теперь нашли детей, или наоборот). Реши и скажи пользователю ЧТО выбрал:
  дети точнее родителя → заведи детей, а запись-родителя предложи удалить;
- `same_name_elsewhere: "<путь>"` — такое же имя, но другой путь: либо копия пака в двух местах
  (укажи пользователю, что дублируется на диске), либо разные версии — тогда уточни имена
  (`PackName (2023)` / `PackName (2026)`), чтобы не путались;
- `dup_in_scan: [...]` — одинаковые имена внутри одного скана, та же логика.
Ничего не удаляй молча: пересечения и дубли — в отчёт, решение за пользователем.

## Шаг 3.6 — ГРАНУЛЯРНОСТЬ: пак = то, что берут целиком
Библиотека на тысячи записей бесполезна человеку и не влезает в браузер. Правило:
**одна запись = один пакет, который реально используют целиком** (Kenney UI Pack, Synty
POLYGON City), а НЕ каждая папка внутри него. Скрипт уже так и делает (спускается максимум
на 2 уровня контейнеров, папки вида Textures/Models/Sprites считает частью пака, предел
400 пакетов за прогон), но если после скана видишь сотни мелких записей одного бандла —
объедини их в одну запись бандла с перечислением состава в `desc`, а не плоди мусор.

## Шаг 4 — Слияние в библиотеку
- В библиотеку пиши ТОЛЬКО поля библиотеки: name, path, desc, tags, kind, use, lic, licdate,
  notes, rating, verdict. Черновиковые (`sample`, `top_ext`, `files_seen`, `kind_guess`,
  `needs_review`, метки дублей) — служебные, в библиотеку НЕ переносить: они раздувают файл.
- Читай существующий `asset-library.json` (нет — создай новый на базе `asset-library.seed.json`,
  seed НЕ перезаписывай: он приезжает с движком), **дедуп по `path`**: уже есть — обнови поля,
  которых не хватало, но НЕ трогай `rating` и `verdict` (это опыт пользователя);
- Пиши обратно `asset-library.json` в корень движка;
- Черновик `asset-scan-draft.json` удали — он временный.
- Пиши в `../forge-data/asset-library.json` (вне движка: обновление стирает всё внутри его папки).
- Кэша нет: этот файл — единственное хранилище. Записал файл → пользователь
  открывает asset-library.html и жмёт «Загрузить», чтобы увидеть результат.

## Шаг 5 — Отчёт пользователю
Таблица: `пак | тип | для каких игр | лицензия | теги`. Отдельно списком:
- ⚠️ **паки с неподтверждённой лицензией** — что проверить и где;
- ❓ **непонятные паки** — по имени ничего не нашлось, нужен взгляд человека;
- дубли, которые обновил, а не завёл заново.

## Границы
- Сканируй КОРЕНЬ коллекции, а не каждую подпапку по очереди: контейнеры распознаются сами,
  и это единственный способ поймать пересечения с прошлыми сканами.
- Более 50 пакетов за раз — предупреди о времени и предложи разбить по подпапкам.
- Не распаковывай архивы ради «посмотреть получше» — листинга достаточно, это гигабайты.
- Не проставляй оценки качества и не выдумывай состав пака, которого не видел.
