# Fill RuStore — Карточка приложения с ASO-оптимизацией

## Цель
Подготовить ВСЕ данные для RuStore с максимальной конверсией в установки. Результат — `StoreData/RUSTORE_LISTING.md` + `StoreData/PUBLISH_GUIDE.md`.

---

## Step 1: Анализ приложения

Прочитать код, wiki/_map.md, wiki/architecture/. Ответить:

1. Что делает? (одно предложение для обычного человека)
2. Для кого? (3 типа пользователей с их ЗАДАЧАМИ)
3. 5-7 главных фич (через ПОЛЬЗУ, не через технологию)
4. Какая фича УНИКАЛЬНАЯ? (чем выделяется среди аналогов)
5. Работает ли офлайн?
6. Бесплатно ли? Есть реклама/покупки?

## Step 2: Подбор ключевых слов

Думай как ПОЛЬЗОВАТЕЛЬ который вбивает в поиск RuStore.

```
ПРАВИЛА:
- "фонарик" а не "flashlight utility"
- "открыть pdf" а не "document parser"
- Включай синонимы: "заметки" + "записи" + "записная книжка"
- Включай задачи: "измерить уровень" + "строительный уровень"
- ОБЯЗАТЕЛЬНО включай: "бесплатно", "без интернета", "офлайн" (если применимо)
  — это самые частые модификаторы в поисковых запросах
- 15-20 слов/фраз
- Ранжируй по частотности: самые популярные запросы ПЕРВЫМИ
```

## Step 5: Написание текстов

### Название (до 30 символов)

```
ФОРМУЛА: [Бренд] — [Ключевая выгода]

ХОРОШО:
  MultiTool — 14 утилит
  UniDocs — Все документы
  FileView — CSV и JSON

ПЛОХО:
  ❌ MultiTool Pro - Universal Utility App v2.1  (английский, длинно)
  ❌ Супер крутой мультитул для всего  (пустое хвастовство)
  ❌ MultiTool Pro  (нет выгоды — зачем ставить?)
```

### Короткое описание (до 80 символов) ⚠️ КРИТИЧЕСКИ ВАЖНО

```
ЭТО ПЕРВОЕ ЧТО ВИДИТ ПОЛЬЗОВАТЕЛЬ ПОД НАЗВАНИЕМ.
Не тратить символы на перечисление фич — дать ПРОДАЮЩИЙ ПОСЫЛ.

ФОРМУЛА: [Выгода/действие] — [контекст] — [бесплатно/офлайн]

ПРАВИЛА:
1. ОБЯЗАТЕЛЬНО слово "бесплатно" (самый частый модификатор поиска)
2. НЕ перечислять фичи — для этого есть полное описание
3. Акцент на ВЫГОДЕ: что пользователь ПОЛУЧИТ
4. Уникальная фича > список банальных

ХОРОШО:
  "Замени 14 приложений одним — измеряй, ищи металл, свети. Бесплатно"
  "14 инструментов офлайн — от компаса до металлодетектора. Бесплатно"
  "Все документы в одном: PDF, DOCX, XLSX. Читай офлайн, бесплатно"
  "Просматривай CSV, JSON, XML с поиском и фильтрами. Бесплатно"

ПЛОХО:
  ❌ "Фонарик, компас, уровень, линейка, металлодетектор и ещё 9 утилит"
     (список фич без выгоды, нет "бесплатно")
  ❌ "Лучшее приложение для инструментов"
     (пустое обещание)
  ❌ "Best multi tool app for Android"
     (английский на русском маркете)
```

### Полное описание (до 4000 символов) ⚠️ ASO-ПРАВИЛА

```
КРИТИЧЕСКИ ВАЖНО — ПЕРВЫЕ ДВЕ СТРОКИ:
RuStore придаёт БОЛЬШИЙ ВЕС словам в начале описания (как и Google Play).
В первых 2 строках ОБЯЗАТЕЛЬНО должны быть:
- Главные ключевые слова
- "бесплатно" и/или "офлайн" (если применимо)
- ЧТО это и ЗАЧЕМ — за 1 предложение

❌ ПЛОХО: "MultiTool Pro — 14 инструментов для дома, ремонта и повседневных задач"
   (нет "бесплатно", нет "офлайн", нет уникальности)

✅ ХОРОШО: "14 бесплатных инструментов офлайн для дома и ремонта — от строительного уровня до металлодетектора. Один раз установил — пользуешься всегда"
   (ключевики в начале, выгода, уникальная фича)

СТРУКТУРА ПОЛНОГО ОПИСАНИЯ:

{Первая строка: ЧТО + ЗАЧЕМ + главные ключевики (бесплатно, офлайн)}
{Вторая строка: уникальная фича или главная выгода}

{emoji} {БЛОК ФИЧЕЙ ПО ТЕМЕ — не все подряд, а сгруппированные}
• {Фича через ПОЛЬЗУ + ключевое слово}
• {Фича}
• {Фича}

{emoji} {ВТОРОЙ БЛОК}
• ...

{emoji} {ТРЕТИЙ БЛОК}
• ...

{emoji} РАБОТАЕТ БЕЗ ИНТЕРНЕТА
{Одно предложение — почему это важно}

{emoji} ДЛЯ КОГО
• {Аудитория + ЗАДАЧА которую решает}
• {Аудитория + ЗАДАЧА}
• {Аудитория + ЗАДАЧА}

{Призыв к действию — "Установите" + название + ключевик}

ПРАВИЛА ТЕКСТА:
- Русский, человеческий язык
- Без жаргона (нет API, SDK, framework, WebView, Capacitor)
- Фичи через ПОЛЬЗУ: "измеряйте прямо экраном телефона" а не "есть линейка"
- Без пустого хвастовства: нет "лучший", "уникальный", "№1"
- Ключевые слова вплетены ЕСТЕСТВЕННО (не спам)
- Эмодзи только в заголовках блоков
- Буллеты через "•"
- Каждый блок 3-5 буллетов (не 10)
```

## Step 6: Стратегия скриншотов ⚠️ ПОРЯДОК РЕШАЕТ

```
ПРАВИЛО: первые 2 скриншота = 80% конверсии.
Пользователь пролистывает дальше только если первые два зацепили.

ПОРЯДОК СКРИНШОТОВ:

1. ПЕРВЫЙ — уникальная фича или общий обзор "N в 1"
   НЕ ставить банальную функцию первой (фонарик = плохо)
   Ставить то что ВЫДЕЛЯЕТ: "Находит металл в стенах" или "14 инструментов"

2. ВТОРОЙ — вторая по уникальности фича
   То что вызывает любопытство или "вау-эффект"

3-5. ОСТАЛЬНЫЕ — по убыванию интересности
   Практичные фичи которые показывают глубину продукта

ПОСЛЕДНИЙ — общий вид / сетка функций (если не был первым)

ТЕКСТ НА СКРИНШОТАХ:
- Формула: {Эмодзи} + {Глагол выгоды в 3-5 слов}
- НЕ просто название инструмента ("Компас")
- А что он ДАЁТ: "Ориентируйся без интернета"

ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:
- Формат: PNG или JPEG
- Размер: 1080x1920 (рекомендуется)
- Ориентация: портрет 9:16
- Минимум 3, рекомендуется 5-8
- Чистый скриншот (без рамок устройства по требованиям RuStore)
- Данные на скриншоте РЕАЛИСТИЧНЫЕ (не "— dB", а "~47 dB")
```

## Step 7: Политика конфиденциальности ⚠️ ОБЯЗАТЕЛЬНО

```
Без политики конфиденциальности RuStore ОТКЛОНИТ публикацию.

Создать файл StoreData/PRIVACY_POLICY.md с содержанием:
- Какие данные собираются (аналитика AppMetrica — анонимная статистика)
- Никакие персональные данные НЕ собираются и НЕ передаются
- Все измерения/данные хранятся ТОЛЬКО на устройстве пользователя
- Контактный email для обращений
- Дата последнего обновления

Файл нужно разместить на любом хостинге (GitHub Pages, свой сайт)
и указать URL при публикации.
```

## Step 8: Создание файлов

```
StoreData/
├── RUSTORE_LISTING.md       ← названия, описания, теги, ключевики
├── ART_GUIDE.md             ← гайд по графике (размеры, цвета, концепты)
├── ART_PROMPTS.md           ← промпты для AI-генерации (иконка, баннер, промо)
├── PUBLISH_GUIDE.md         ← пошаговая инструкция публикации
├── PRIVACY_POLICY.md        ← политика конфиденциальности
└── screenshots/             ← скриншоты
    └── README.md            ← порядок и что на каждом
```
