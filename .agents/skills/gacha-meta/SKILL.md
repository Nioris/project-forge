# $gacha-meta — гача-мета с крутками за рекламу

Цель: слой случайных наград поверх любой игры. Крутки = за RV (наша ads-only модель) +
немного за игровую валюту. Исследовано 2026-07: дейли-колесо = строитель привычки D1-D7;
pity-гарантия обязательна; механика подбирается под стадию игрока.

## Каталог механик (выбрать 2-3 под игру, не все сразу)

| # | Механика | Что даёт | Крутка за | Когда работает | Жанр-фит |
|---|---|---|---|---|---|
| 1 | **Дейли-колесо фортуны** (сброс в полночь) | валюта/бустеры/1 редкий сектор | 1 бесплатно + 1-2 за RV | привычка D1-D7, «зайти за спином» | ЛЮБОЙ — базовый выбор №1 |
| 2 | **Гача-баннер** (крутка из пула) | СКИНЫ героя/юнитов, расходка, валюта | RV или валюта; 10-крутка со скидкой | коллекционирование D8-D30 | игры с героем/юнитами |
| 3 | **Дейли-календарь** (7/30 дней) | растущие награды, день 7 = жирный | вход бесплатно; ×2 за RV | серия визитов, страх пропуска | ЛЮБОЙ |
| 4 | **Скретч-карта** | мгновенный приз, 3 поля «сотри» | 1/день бесплатно, ещё за RV | реактивация остывших, низкий порог | казуал/сессионки |
| 5 | **Сундук по таймеру** | открывается через N мин ИЛИ сразу за RV | RV = мгновенно | «вернись через час» + RV-конверсия | стратегии/менеджеры |
| 6 | **Коллекция-альбом** | собери сет скинов/карточек → мега-приз | дубли из гачи #2 | длинная цель D8-D30 | с гачей #2 в паре |
| 7 | **Лимитированный баннер** | сезонный скин, баннер на 5-7 дней | RV-крутки | срочность, возвраты, к $seasonal-event | с гачей #2 |

## Что класть в пулы (по убыванию частоты)
Валюта (60-70%) → расходка/бустеры под игру (20-25%: ускорители, второй шанс, +ход) →
СКИНЫ (5-10%: визуал героя/юнитов/поля — НЕ сила, чтобы не ломать баланс) →
джекпот-редкость (1-2%: эксклюзивный скин/большая сумма).

## Железные правила
1. **Pity-система ОБЯЗАТЕЛЬНА**: гарантированная редкость каждые N круток (N=10-15 для
   колеса, 20-30 для гачи), счётчик виден игроку («до редкой: 7 круток»), хранится в сейве.
2. **Шансы показывать** (кнопка «Шансы» у баннера) — честность = отзывы = рейтинг 2.13.
3. **Скины = визуал, не сила.** Pay-to-win из RV-гачи убивает баланс и ретеншен.
4. **Дубли конвертируются** (в валюту или прогресс альбома #6) — дубль-в-никуда бесит.
5. RV-вайринг по доктрине monetization-design: крутка = ЖЕЛАНИЕ игрока, кнопка честная
   («крутка за рекламу»), 4.5 жест, 4.7 пауза, сейв до показа. Гача-крутки НЕ входят в
   лимит дифференциации хуков — это отдельная система со своим RV-бюджетом.
6. Возрастной рейтинг: рулетки/гача без реальных денег на Яндексе ок, но НЕ оформлять
   как казино (без 777/рулетки-казино-эстетики) — влияет на категорию и восприятие.

## Реализация (universal-модуль)
`gacha.js`: конфиг пулов {id, weight, type, payload}, weighted-roll + pityCounter,
интеграция с сейвом (player.setData), UI: баннер + анимация крутки 1.5-2с (предвкушение =
половина удовольствия) + витрина приза. Расходка/скины — через существующие системы игры;
нет системы скинов → простейшая: цвет/шапка героя из массива.

## Порядок внедрения в существующую игру
1. Выбери 2-3 механики по таблице жанр-фит (дефолт: колесо #1 + сундук #5 или гача #2).
2. Собери пул из ТОГО ЧТО ЕСТЬ в игре (валюта/бустеры) + добавь 4-8 скинов.
3. Вшей pity + показ шансов + конверсию дублей.
4. Playtest: крутка работает, награда выдаётся, отказ от RV не ломает, сейв переживает F5.
5. Числа круток/наград — в metrics.md (RV/DAU должен вырасти к target 2.5).

## Канонический быстрый путь для модульного merge-grid

Если у существующей игры уже есть `wiki/architecture/modules.json`, `state.grid`, `saveState/loadState` и merge-сетка, не реконструируй её модули текстом. Запусти атомарный Forge-интегратор:

```text
node ../project-forge/scripts/integrate-gacha.mjs WorkProgress/<game>
node ../project-forge/scripts/modularize-existing-project.mjs WorkProgress/<game>/index.html --refresh
node ../project-forge/scripts/modularize-existing-project.mjs WorkProgress/<game>/index.html --check
node ../project-forge/scripts/check-gacha-integration.mjs WorkProgress/<game>
```

Через GigaChat вызывай эти команды инструментом `forge_script`, передавая имя `scripts/<file>.mjs` и project-relative args. Интегратор одной транзакцией согласует `state.gachaQueue`, основной save/load, reset, core/integration-модули и порядок подключения. Он сохраняет backup и останавливается на неизвестных anchors вместо частичной перезаписи.

Сфокусированный browser-check обязателен: он реально кликает кнопку, проверяет `state.grid`, основной localStorage save, полную сетку, очередь, F5 и выдачу после освобождения клетки. Обычный playtest без клика по гаче не является доказательством этой функции.
