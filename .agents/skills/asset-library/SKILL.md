# $asset-library — сначала ищем готовое, потом генерируем

Библиотека источников живёт в **`asset-library.json`** в папке `../forge-data/` (рядом с движком; в корне движка — только наследие, читается как запасной вариант) (файл ПОЛЬЗОВАТЕЛЯ, обновления движка его не трогают; если его ещё нет — возьми за основу `asset-library.seed.json`) (единственный источник данных;
`asset-library.html` рядом с дашбордом — просмотрщик/редактор, который ЗАГРУЖАЕТ и СОХРАНЯЕТ
этот файл, ничего не кэшируя). Каждая запись: название, путь, тип, описание,
теги, **лицензия** и **notes — инструкция по извлечению**.

## Правило порядка (обязательное)
Перед `asset-generation` для типовых объектов (пропсы, тайлы, иконки, 3D-болванки, звуки
интерфейса) **сначала загляни в библиотеку**. Генерация — для уникального: герой, стор-арт,
всё, что определяет лицо игры. Смысл: библиотечное дешевле, быстрее и стилистически
консистентнее внутри пака.

## Как искать (НЕ читай файл целиком — он больше мегабайта)
```
node <движок>/scripts/asset-find.mjs "слова запроса" [--kind 2d|3d|audio|unity|font|ui]
                                      [--use 2d|3d] [--limit 20] [--json]
```
Работает из папки игры и из движка: файл ищется по порядку `./forge-data` → `../forge-data`
→ `<движок>/../forge-data` → `<движок>/` (наследие). Из игры-соседа:
`node ../project-forge/scripts/asset-find.mjs "фэнтези оружие" --kind 2d`.
Возвращает только подходящие записи, отсортированные по совпадению тегов и ОЦЕНКЕ пользователя;
`--json` — машинный формат; источники с `lic: no` помечаются предупреждением.

## Процедура
1. Прочитай `asset-library.json`. Нет файла → посмотри `asset-library.seed.json` (образец) и
   скажи пользователю: «библиотека не заведена — открой asset-library.html, добавь источники,
   нажми Экспорт для Forge»; затем иди генерировать.
2. Отфильтруй по трём осям:
   - **`use`** — под какую игру источник: `2d` / `3d` / `any` (3D-модели можно рендерить в
     спрайты, такие помечены `any`). Для 2D-игры не предлагай `use:"3d"`, если в notes нет
     рецепта рендера в спрайты;
   - **`kind`** — что это (2d/3d/audio/unity/font/ui);
   - слова запроса в `tags` и `desc` (теги — главный канал поиска).
   Затем сортируй по **`rating`**: сначала 5★, потом ниже. **`rating` 1-2 — не предлагать**
   (проверено плохим), кроме случая «больше нечего», и тогда честно скажи об этом.
   Нашёл кандидата → покажи пользователю: название, путь, лицензия, оценка — и ЧТО возьмёшь.
3. **Лицензионный гейт (жёстко):**
   - `free` (CC0/MIT) — берём свободно;
   - `attr` (CC-BY) — берём, но обязателен экран/строка кредитов в игре, запиши это в задачи;
   - `paid` — берём по условиям продавца (Synty и подобные разрешают использование в играх,
     но НЕ перепродажу исходников);
   - `no` (NC/GPL) — **не берём никогда**, наши игры коммерческие (реклама = коммерция).
4. Извлекай строго по `notes` записи — там команды и подводные камни конкретного источника
   (для Unity-паков: не распаковывать библиотеку целиком, вытаскивать только нужные типы,
   смотреть содержимое FBX перед резкой, конвертировать через Blender, оптимизировать
   gltf-transform перед укладкой в проект).
5. **Стилевой гейт:** взятое обязано соответствовать `art-direction` игры (палитра, плотность
   деталей). Не соответствует — перекрась/пересобери палитру или откажись от источника.
   Чужой стиль рядом с генерённым — самый заметный признак дешёвой сборки.
6. **Провенанс:** каждый взятый файл → строка в `wiki/assets-provenance.md`:
   `файл | источник (name) | лицензия | дата`. Через полгода никто не вспомнит, откуда
   спрайт и можно ли его продавать — запись обязательна.
7. После укладки — `node scripts/asset-catalog.mjs <игра>`: посмотреть новинки в общем строю.

## Чего не делать
- Не распаковывать целиком большие библиотеки (десятки гигабайт).
- Не тащить в проект движковую специфику (.prefab, .unity, .mat, .shader, .meta) — вне
  движка бесполезна. НО сам пак при этом пригоден: см. раздел 📦 ниже.
- Не «дополнять» библиотеку самостоятельно: источники добавляет пользователь в HTML.

## Оценка качества — библиотека учится
После того как ассеты из источника легли в игру и ты увидел результат:
- предложи пользователю поставить оценку 1-5 в `asset-library.html` (звёзды в карточке) и
  дай СВОЮ короткую рекомендацию с обоснованием: качество мешей/спрайтов, попадание в стиль,
  трудоёмкость извлечения, соответствие описанию;
- если источник подвёл (кривые пивоты, неверные размеры, стиль не тот, лицензия оказалась
  строже) — прямо скажи «предлагаю ★1-2» и объясни; такие источники Forge перестанет
  предлагать автоматически.
Смысл: через несколько игр библиотека сама вытолкнет наверх то, что реально работает, а
слабые источники осядут внизу и уйдут из выдачи.

## 📦 UNITY-ПАКИ — ЭТО ОБЫЧНЫЕ АССЕТЫ, а не «только для Unity»

Полевой кейс: исполнитель видел `kind: unity` и проходил мимо, решив, что пак пригоден только
в Unity. **Это ошибка.** `.unitypackage` — просто tar.gz-архив, внутри которого лежат
**обычные FBX-модели, PNG-текстуры, WAV-звуки**. Для нашего web-стека они годятся полностью,
нужен только шаг конвертации.

**Правило: `kind: unity` = склад моделей/текстур/звуков. Не пропускать при поиске.**
Для 3D-игры такой пак — часто лучший источник (один атлас на весь набор, единый стиль,
готовые LOD'ы).

### Что берём и что оставляем
| Берём | Оставляем в паке |
|---|---|
| `.fbx`, `.obj` — модели (→ glb) | `.prefab`, `.unity`, `.asset` — сцены/префабы Unity |
| `.png/.jpg/.tga` — текстуры (→ webp) | `.mat`, `.shader`, `.shadergraph` — материалы Unity |
| `.wav/.mp3/.ogg` — звуки | `.controller`, `.anim` (если нет своего риг-пайплайна) |
| `.ttf/.otf` — шрифты | `.cs`, `.meta`, вложенный `URP_ExtractMe.unitypackage` |

Материалы **не нужны**: цвет и текстуру мы подключаем сами при экспорте в glb.

### Извлечение (общая схема; частности — в `notes` конкретного источника)
```
node unity-extract.mjs <пак> ./work --only "*.fbx,*.png"     # только нужные типы
blender --background --python fbx_split.py -- --fbx <файл> --list          # что внутри
blender --background --python fbx_split.py -- --fbx <файл> --out ./glb --filter "Name*"
gltf-transform optimize in.glb out.glb --compress draco --texture-compress webp
```
Никогда не распаковывать библиотеку целиком (десятки гигабайт) — только нужный пак и типы.

### Для 2D-игры Unity-пак тоже полезен
Спрайты, UI-киты, иконки и звуки внутри — обычные PNG/WAV, берутся напрямую без Blender.
Поэтому `use` у таких паков часто `any`, а не только `3d`.
