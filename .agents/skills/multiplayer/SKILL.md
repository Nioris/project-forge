# $multiplayer — свой бэкенд для игры (async / sync)

Платформа мультиплеера НЕ даёт (подтверждено поддержкой Яндекса): всё живёт на своём сервере.
В движке два готовых профиля, оба разворачиваются docker-compose на VPS пользователя.

## Кто что делает
- **Решение «делаем ли мультиплеер»** — пользователь, 🔴-блоком на фазе 2 (это деньги: сервер
  постоянно стоит). Дизайнер обязан спросить, а не решить сам.
- **Развёртывание и проверка бэкенда** — агент `backend-builder` (фаза 3, системный спринт).
- **Игровая логика хода** — исполнитель фазы 3 в `applyAction()` на сервере.

## Шаг 0 — Выбор профиля (спроси, если не очевидно)
| Признак игры | Профиль |
|---|---|
| ходы по очереди, кланы, общий мир «пока ты спал», обмены, свой лидерборд | **async** |
| действия видны другим в ту же секунду: .io, экшен, гонки, совместный бой | **sync** |
Сомнение → **async**: дешевле в эксплуатации (нет постоянных соединений), проще, и
большинство «мультиплеерных» ощущений даёт без реалтайма.

## Профиль ASYNC — `templates/backend/async/`
Состав: Caddy (TLS автоматом) + Fastify API + PostgreSQL. Готовое из коробки: проверка подписи
игрока, игроки, кланы и участники, лента действий (`/clan/:id/feed?since=`), свой лидерборд,
грубый рейт-лимит 60 запросов/мин на игрока.
1. Возьми профиль из движка (шаблоны по играм НЕ раскатываются — это движковая папка):
   ```
   node ../project-forge/scripts/use-template.mjs backend/async ./backend
   node ../project-forge/scripts/use-template.mjs html5/mp-client.js ./mp-client.js
   ```
   Существующие файлы скрипт не перезаписывает. Заполни `.env` по `.env.example`.
2. Логику игры пиши в `applyAction()` в `api/server.mjs` — это единственное место, где
   рождается результат хода.
3. Клиент: `mp-client.js` (взят командой выше) → `createMP({base, ysdk})`, после SDK-инициализации.
4. Развёртывание и правила — `README.md` профиля.

## Профиль SYNC — `templates/backend/sync/` (Colyseus)
Ставится рядом тем же compose, отдельный сервис. Комнаты, авто-синхронизация состояния,
матчмейкинг. Клиент — `colyseus.js` (обычный JS, без движка).

## Железные правила (нарушение = дыра или отказ)
1. **ID игрока — только из проверенной подписи платформы.** `getUniqueID()` с клиента не
   доверять никогда: подделка = вход в чужой клан и порча чужого прогресса.
2. **Клиент шлёт НАМЕРЕНИЕ, сервер считает РЕЗУЛЬТАТ.** Приняли «у меня 5000 золота» —
   экономика мертва в первый день.
3. **Только `https://` и `wss://`** с валидным сертификатом: игра открыта по HTTPS, смешанный
   контент браузер заблокирует. CORS — строго домены платформы.
4. **Игра обязана работать без сервера.** Сеть упала → одиночный режим, прогресс в облаке
   платформы; мультиплеер — надстройка, не условие запуска. Иначе падение VPS = отказ игры и
   рейтинг вниз.
5. **Секретный ключ — только на сервере.** В билд игры не попадает никогда (проверь grep перед
   релизом).
6. **RuStore/Capacitor**: подписи Яндекса там нет — нужен свой механизм аккаунта. Если игра
   пойдёт на обе платформы, реши схему аккаунтов ДО первого релиза, иначе один игрок
   размножится на две записи.
7. **Стоимость**: сервер = постоянный расход. Для ads-only игры прикинь, отбивает ли
   мультиплеер свой VPS (async — обычно да, sync — только если он ядро игры).

## Проверка перед сдачей
- `curl https://<домен>/api/health` → ok;
- запрос с ПОДДЕЛАННОЙ подписью → 401 (проверь руками, это главный чек);
- выключенный сервер → игра запускается и играется в одиночном режиме;
- grep по билду: секретного ключа нет.
