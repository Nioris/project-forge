# Promo Screens — Промо-скриншоты для магазинов

## ГЛАВНОЕ ПРАВИЛО
Скриншот в магазине — это НЕ скриншот приложения. Это РЕКЛАМНАЯ КАРТОЧКА.
Пользователь листает карточки за 1-2 секунды. Если первая не зацепила — ушёл.

ChatGPT/DALL-E 2025+ умеет рисовать текст на изображениях. Используем это:
генерируем ГОТОВЫЕ промо-карточки с текстом, фоном и визуалом — без Figma.

## Step 1: Стратегия карточек

### Порядок = воронка продаж

```
КАРТОЧКА 1 — ХУК (зацепить за 1 сек)
  Что: УНИКАЛЬНАЯ фича или "N в 1"
  Цель: "ого, это интересно" → листаю дальше
  НЕ ставить первой: банальную фичу (фонарик, калькулятор)
  Ставить первой: то что ВЫДЕЛЯЕТ (металлодетектор, AI-помощник, 14 в 1)

КАРТОЧКА 2 — ДОКАЗАТЕЛЬСТВО (показать что это серьёзно)
  Что: вторая уникальная фича или ключевая механика
  Цель: "о, тут реально много всего"

КАРТОЧКА 3 — ГЛУБИНА (показать объём)
  Что: обзор всех функций или третья фича
  Цель: "хочу попробовать"

КАРТОЧКИ 4-8 — ДЕТАЛИ (для тех кто уже заинтересован)
  Что: остальные фичи по убыванию интересности
```

### Для каждой карточки определить:

```
1. ЗАГОЛОВОК (3-6 слов, крупно, цепляет)
   - Глагол действия: "Находи", "Измеряй", "Открывай"
   - ИЛИ выгода: "14 инструментов в кармане"
   - ИЛИ вау-факт: "Видит металл сквозь стены"

2. ПОДЗАГОЛОВОК (1 строка, мельче, поясняет)
   - Конкретика: "Через магнитометр телефона"
   - ИЛИ пример: "PDF, DOCX, XLSX, CSV и другие"

3. ВИЗУАЛ (что на картинке)
   - Mockup телефона с КОНКРЕТНЫМ экраном приложения
   - ИЛИ абстрактная иллюстрация фичи
   - ИЛИ 3D-объект символизирующий функцию

4. ФОН (атмосфера)
   - Градиент из цветов приложения
   - ИЛИ контекстная сцена (мастерская, офис, природа)
   - НИКОГДА белый или чёрный однотонный

5. АКЦЕНТ (что привлекает взгляд)
   - Свечение, частицы, стрелки, выделение цветом
```

## Step 2: Формулы промптов для ChatGPT

ChatGPT/DALL-E хорошо рисует текст НА РУССКОМ. Используем это.

### Формула промо-карточки (вертикальная, 1080x1920)

```
Создай вертикальную промо-карточку для магазина приложений, 1080x1920.

ТЕКСТ:
- Вверху крупным жирным шрифтом (белый на тёмном фоне): "{ЗАГОЛОВОК}"
- Под ним мельче: "{ПОДЗАГОЛОВОК}"

ВИЗУАЛ:
- В центре: {описание mockup телефона / иллюстрации / 3D-объекта}
- {Описание деталей экрана если mockup}

ФОН:
- {Описание фона: градиент, цвета, атмосфера}
- {Декоративные элементы: частицы, линии, свечение}

СТИЛЬ:
- Профессиональный маркетинговый, как у топ-приложений в App Store
- Чистый, современный, не перегруженный
- Текст чёткий и читается даже в превью
```

### Формула промо-карточки (горизонтальная, 16:9 для Яндекс)

```

- Под ним мельче: "{ПОДЗАГОЛОВОК}"

ВИЗУАЛ:
- Справа: {mockup / иллюстрация}

ФОН и СТИЛЬ: {как выше}
```

## Step 5: Правила качества

```
ТЕКСТ НА КАРТОЧКЕ:
  ✅ Заголовок 3-6 слов (читается за 1 секунду)
  ✅ Глагол действия или вау-факт (не название фичи)
  ✅ Подзаголовок — конкретика или пример
  ✅ Нижняя строка: "Бесплатно" / "Офлайн" / цифра
  ❌ Не больше 3 строк текста на карточке
  ❌ Не мелкий текст (должен читаться в превью магазина)

ВИЗУАЛ:
  ✅ Один фокус — телефон ИЛИ иллюстрация (не оба мелко)
  ✅ Mockup телефона — с РЕАЛЬНЫМ экраном приложения
  ✅ Контраст: светлый объект на тёмном фоне (или наоборот)
  ❌ Не пустой экран телефона
  ❌ Не скриншот без обрамления
  ❌ Не фото (стилизованная графика лучше конвертит)

ФОН:
  ✅ Градиент из 2-3 цветов приложения
  ✅ Декоративные элементы (частицы, линии, свечение) на 10-20%
  ❌ Не белый/чёрный однотонный
  ❌ Не перегруженный деталями (фон не должен конкурировать с текстом)

ОБЩЕЕ:
  ✅ Каждая карточка самодостаточна (понятна без других)
  ✅ Единый стиль всех карточек (цвета, шрифт, композиция)
  ✅ Первая карточка — уникальная фича (не банальная)
```

## ⚠️ ТРИ ЖЕЛЕЗНЫХ ПРАВИЛА (полевые дефекты 2026-07-18 + требования 8.3.1)

### 1. НАТИВНОЕ разрешение съёмки — апскейл ЗАПРЕЩЁН
Полевой дефект: снимали ~470px и растягивали до 1920 → мыло → нарушение 8.3.1 («без
пиксельных артефактов сжатия»). Правило: viewport puppeteer/браузера ставится РАВНЫМ целевому
размеру ДО съёмки:
- десктоп: 1920×1080 (16:9);
- мобила портрет: 1080×1920 (9:16);
- мобила ландшафт: 1920×1080.
Уменьшать можно (LANCZOS), увеличивать — НИКОГДА. Сплющивать под пропорцию — отказ; только кроп.
Пиксель-арт: следи, чтобы integer-скейл игры на большом вьюпорте не давал полуразмытых пикселей
(image-rendering: pixelated обязан работать).

### 2. Скриншот = ГЕЙМПЛЕЙ С ИНТЕРФЕЙСОМ в момент действия
Полевой дефект: кадры «пустое поле без HUD» (красиво, но непонятно, ЧТО за игра). Правила кадра:
- HUD/интерфейс ВИДЕН (очки/ресурсы/кнопки) — исключение только для чисто-атмосферного 1-го кадра;
- момент ДЕЙСТВИЯ: бой/строительство/погоня, не пустая карта и не одни меню;
- тест кадра: «понятно ли за 2 секунды, во что тут играют и что делать?» Нет → перекадрировать;
- 8.3.1: без затемнения (сними паузу/оверлеи), без одноцветных кадров, БЕЗ debug-панели (!),
  без фейковых мобильных полос-фонов (запрещены новостью платформы);
- минимум 3 кадра, разные моменты игры (ранний/средний/поздний геймплей).

### 3. ДВА НАБОРА + локализация
Консоль требует раздельно:
- `screens/desktop/` — 16:9, всегда;
- `screens/mobile-portrait/` (9:16) и/или `screens/mobile-landscape/` — по ориентации из
  черновика (портретная игра = портретные скрины ОБЯЗАТЕЛЬНЫ).
Языки: скриншоты локализуются под КАЖДЫЙ заявленный язык (снимай с ?lang=xx / setLang;
скрин с русским UI в EN-каталоге = замечание). Точные пиксельные стандарты полей — в самой
форме черновика, сверяйся при загрузке.

### Проверка фактом (как Step 4.5 asset-generation)
После съёмки скрипт печатает фактические размеры каждого файла; размер ≠ целевому или
upscale-происхождение (исходник меньше цели) → FAIL, пересъёмка.

## 🎬 ПРОМО-ВИДЕО геймплея (v4.31.1 — в пару к скриншотам)

Лимиты видео — В ФОРМЕ черновика (п.5.3; типично ~28с / до 100МБ) + 8.3.1 (качество).
Запись автоматом (скрипт САМ играет и пишет экран):
```
node scripts/record-promo.mjs WorkProgress/{Game}/ --secs 26                  # десктоп 1920×1080
node scripts/record-promo.mjs WorkProgress/{Game}/ --secs 26 --w 1080 --h 1920  # мобильный портрет
```
Требует ffmpeg (Windows: winget install ffmpeg). Выход: mp4 h264 + СДАЧА ФАКТОМ
(разрешение/длительность/размер печатаются, несоответствие = exit 1).
Правила содержимого: ГЕЙМПЛЕЙ с первой секунды (меню скрипт прокликивает сам), без
debug-панели, без пустых кусков; --keys подбери под игру; ГЛАЗАМИ проверь итог (8.3.1) —
скучное видео хуже отсутствующего, перепиши с более активного момента. Звука нет — промо
в каталоге и так автоплеится без звука. Точный лимит секунд/МБ сверь в форме при загрузке.

## 🎬 Промо-ВИДЕО (снимается в ту же сессию, что скриншоты)

Требование 8.3: **реальный геймплей ≥70% длительности** — видео из логотипов/катсцен завернут.
Видео поднимает фичер-скор игры (готовность к продвижению). Лимит длины/формата — в форме
Консоли (сейчас ≤28с, mp4 — сверяй при загрузке).

### Правила ролика
- **Длина ≤28с, геймплей ≥70%** (т.е. максимум ~8с на всё негеймплейное — и лучше 100% геймплея);
- структура: **0-3с = хук** (сразу действие, самый сочный момент игры — каталог автоиграет без
  звука, первые секунды решают всё) → 2-3 разных момента геймплея (ранний/средний/поздний, как
  скриншоты) → финал = вау-фича;
- **нативное разрешение** (1920×1080 с той же сессии local-stage), апскейл запрещён (8.3.1);
- HUD виден, момент действия, БЕЗ debug-панели, без пауз-затемнений;
- **без наложенного текста/логотипов** (правило Step 4.4 действует и тут; читаемость без
  звука обеспечивает геймплей, не титры);
- звук допустим, но ролик обязан работать БЕЗ него (каталог мьютит автоплей).

### Как снимать — ОСНОВНОЙ путь: канонический рекордер (не пиши свой!)
```
node scripts/record-promo.mjs <игра> [--orientation portrait] [--trim-start 6] [--keys "wasd "]
```
Сам: поднимает сервер с мок-SDK → puppeteer играет (меню → сетка кликов/тач → клавиши) →
page.screencast пишет сырьё → GPU-монтаж (h264_nvenc, ≤28с) → ffprobe-факты. Выход:
screens/video/promo-desktop.mp4 + promo-mobile.mp4 (по ориентации). Сырьё raw-*.webm остаётся —
неудачный хук лечится перемонтажом с другим --trim-start, без пересъёмки.
ЗАПРЕЩЕНО писать одноразовые рекордеры в играх — только канонический скрипт движка.

### Альтернатива качества (когда автоплей вялый): руками
1. `node scripts/local-stage.mjs <игра>` → играешь сам 30-40с сочного.
2. Захват Win+G / OBS.
3. Обрежь до ≤28с (начало = хук, не меню!) — обработка ТОЛЬКО через GPU (NVENC),
   CPU-кодирование запрещено (медленно и греет машину зря):
