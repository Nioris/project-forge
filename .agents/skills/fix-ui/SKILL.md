# Fix UI/UX — Советчик по визуалу и удобству

## FIRST — Patch или Redesign? (главная развилка)

Прежде чем формулировать промпт, классифицируй запрос. Это решает проблему «прошу переделать —
вносит мелкую правку».

**PATCH** — точечная правка одного элемента. Слова указывают на КОНКРЕТНЫЙ элемент:
"эта кнопка мелкая", "поменяй цвет заголовка", "сдвинь иконку". → формулируй узкий промпт.

**REDESIGN** — недовольство РЕЗУЛЬТАТОМ В ЦЕЛОМ. Слова: "переделай", "это говно", "не то",
"не подходит под игру", "выглядит дёшево", "по-прежнему плохо", "опять не так", "ну такое",
"скучно", "не нравится". → НЕ мелкая правка. Промпт ДОЛЖЕН требовать редизайн через спек:

```
Это не патч, а редизайн. Прочитай $art-direction и $ui-pipeline. Сначала зафиксируй
art-direction спек под ЭТУ игру (жанр, палитра по жанру, тон), потом переделай интерфейс
ПОД спек — не косметика. Редизайн, меняющий <30% поверхности, не считается. После — прогони
self-critique loop из $art-direction на скриншоте ($ui-review) ДО показа: richness, readability,
hierarchy, intentionality, ни одна ось ≤ 3.
```

Правило: если пользователь повторно недоволен тем же экраном — это сигнал, что **направление**
не то, а не что «правка была мала». Возвращайся к спеку и оспаривай саму концепцию, не подкручивай.

## Дизайн и UX ПОД игру (фикс «не подбирает под игру»)

UI должен матчить жанр и платформу, а не быть generic. Быстрый маппинг (детали — $art-direction,
$ui-pipeline pattern base):

| Жанр | Визуальный тон | UX-паттерны |
|------|----------------|-------------|
| Hyper-casual / arcade | Яркий, крупный, минимум хрома | 1 главная кнопка, мгновенный рестарт, нет меню-лабиринтов |
| Idle / clicker | Числа крупно, прогресс-бары, "juicy" | Tap-target большой, авто-сейв виден, offline-доход поп-ап |
| Puzzle | Чисто, спокойно, высокий контраст фишек | Undo, подсказка, уровни-сетка, мало текста |
| RPG / adventure | Атмосферный, тематичные рамки/шрифт | Инвентарь, тултипы, карта, диегетичные панели |
| Shooter / action | Тёмный HUD, неон-акценты, высокий контраст | HUD по краям (центр чист), полупрозрачные контролы |
| Sim / strategy | Информационно-плотный, сдержанная палитра | Тулбары, контекст-меню, плотность данных ок |

Если жанр неясен — это единственный уместный вопрос (см. Non-Negotiable). Платформа: mobile →
touch-targets ≥48px, контролы по краям, safe-area; desktop → можно плотнее, hover-состояния.

## Как работает

Пользователь описывает проблему НЕФОРМАЛЬНО:
- "кнопки мелкие"
- "на мобилке всё съезжает"
- "цвета унылые"
- "непонятно куда нажимать"
- "хочу тёмную тему"
- "слишком много всего на экране"

Ты НЕ ИСПРАВЛЯЕШЬ. Ты:
1. Понимаешь категорию проблемы
2. Определяешь какой скил нужен
3. Формулируешь точный промпт ОДНОЙ СТРОКОЙ
4. Если проблема сложная — даёшь план из нескольких промптов по порядку

## Категории UI/UX проблем и какие скилы использовать

### Визуал (как выглядит)
Слова: некрасиво, уныло, скучно, плоско, цвета, палитра, иконки, шрифт, тени, градиенты, glow
Скил для игр: visual-upgrade
Скил для приложений: app-settings (тема), tailwind-mobile

### Компоновка (где что расположено)
Слова: съезжает, вылезает, не влезает, перекрывает, наслоение, отступы, padding, margin, overflow
Скил: mobile-adapt, mobile-game-ui, app-ux-polish

### Размеры (большое/мелкое)
Слова: мелкий, огромный, не нажать, tiny, большой, шрифт, кнопки, touch target
Скил: mobile-game-ui (для игр), app-ux-polish (для приложений)

### Адаптивность (разные экраны)
Слова: мобилка, планшет, десктоп, responsive, поворот, ориентация, safe area, notch
Скил: mobile-adapt, tailwind-mobile

### Навигация (куда нажимать)
Слова: непонятно, потерялся, куда нажать, нет кнопки назад, нет меню, запутался
Скил: mobile-game-ui (для игр), app-ux-polish (для приложений)

### Состояния экрана (пусто/загрузка/ошибка)
Слова: пустой экран, белый экран, загрузка, ошибка, нет данных, крутилка
Скил: app-ux-polish (7 состояний), game-polish (loading screen)

### Анимации и feedback (отклик на действия)
Слова: не понятно что нажалось, нет анимации, резко, без плавности, мёртвый интерфейс
Скил для игр: visual-upgrade (easing, tweens), game-polish (transitions)
Скил для приложений: app-ux-polish (micro-interactions)

### Тёмная тема
Слова: тёмная тема, dark mode, светлая, глаза болят, ночной режим
Скил: app-settings

## Формат ответа

Для простой задачи:
```
Вот что написать:

[промпт одной строкой]
```

Для сложной задачи — план по шагам:
```
Тут нужно в несколько шагов. Копируй и вставляй по одному:

Шаг 1: [промпт]
Шаг 2 (после выполнения первого): [промпт]
Шаг 3 (после выполнения второго): [промпт]
```

## Примеры

Пользователь: "кнопки мелкие на мобилке"

Ответ:
```
Вот что написать:

Пройди по всем кнопкам и интерактивным элементам в приложении. Минимальный touch target 48px (лучше 56px для основных действий). Увеличь все кнопки меньше 48px, добавь padding если текст внутри впритык. Проверь на экране 375x667 что ничего не наслаивается после увеличения.
```

Пользователь: "на мобилке всё съезжает"

Ответ:
```
Вот что написать:

Прочитай скил mobile-adapt и сделай полный аудит адаптивности. Проверь на размерах 375x667, 390x844, 414x896. Исправь все overflow, вылезающие элементы, горизонтальный скролл. Все фиксированные размеры в px замени на относительные (%, vw, vh, clamp). Flex/grid вместо абсолютного позиционирования.
```

Пользователь: "цвета унылые хочу покрасивее"

Ответ для приложения:
```
Вот что написать:

Прочитай скил app-settings и создай систему тем через CSS-переменные. Светлая тема: чистые белые карточки с мягкими тенями, акцентный цвет синий (#3b82f6). Тёмная тема: фон #0f0f0f, карточки #1a1a1a, акцент голубой (#60a5fa). Все цвета через var(), переключение по кнопке в настройках. Добавь subtle-градиенты на заголовки и плавные transition при смене темы.
```

Ответ для игры:
```
Вот что написать:

Прочитай скил visual-upgrade. Создай палитру по жанру игры (см. таблицу в скиле). Замени все плоские fillStyle на градиенты. Добавь glow на пули/подбираемые предметы, тени на персонажей, параллакс-фон из 3 слоёв. Фон НЕ чёрный — минимум градиент.
```

Пользователь: "непонятно что нажалось, интерфейс мёртвый"

Ответ:
```
Вот что написать:

Добавь visual feedback на все интерактивные элементы: кнопки при нажатии scale(0.95) с transition 0.1s, при отпускании bounce обратно. Успешные действия — зелёный toast внизу. Удаление — undo toast на 5 секунд. Переходы между экранами — fade 200ms а не instant. Haptic feedback через navigator.vibrate(10) на важных действиях.
```

Пользователь: "на мобилке слишком много кнопок, не пойму куда жать"

Ответ для игры:
```
Вот что написать:

Прочитай скил mobile-game-ui. Оставь максимум 4-5 постоянных кнопок на экране. Остальные действия убери в radial wheel (долгое нажатие на кнопку gear). Редко используемые (настройки, инвентарь) — в полноэкранные панели по отдельной кнопке. Кнопки полупрозрачные (opacity 0.3), не блокируют обзор.
```

Ответ для приложения:
```
Вот что написать:

Прочитай скил app-ux-polish. Сделай аудит всех экранов: на каждом оставь только 1 главное действие (primary button) и максимум 2-3 второстепенных. Остальное в меню (три точки) или на отдельный экран. Нижняя навигация максимум 5 табов. Убери все дублирующие кнопки.
```

Пользователь: "хочу тёмную тему"

Ответ:
```
Тут нужно в несколько шагов:

Шаг 1: Прочитай скил app-settings и добавь систему тем: все цвета через CSS-переменные (--bg-primary, --text-primary и т.д.), три режима (светлая/тёмная/системная), переключение в настройках. Перекрась ВСЕ хардкод-цвета на переменные.

Шаг 2 (после первого): Проверь ВСЕ экраны в тёмной теме. Найди места где белый текст на белом фоне, невидимые бордеры, неконтрастные элементы. Исправь.
```

Пользователь: "пустой экран когда нет данных, надо что-то показать"

Ответ:
```
Вот что написать:

Прочитай скил app-ux-polish секция empty states. Для каждого списка/экрана где может быть пусто — добавь empty state: крупная иконка по смыслу, заголовок (что тут будет), подсказка (как добавить), кнопка действия. Анимация fadeIn при появлении. Также добавь skeleton-loading пока данные загружаются.
```

## Non-Negotiable
- [ ] СНАЧАЛА классифицировать: patch (узкий элемент) или redesign (недовольство результатом)
- [ ] "Переделай"/"не подходит"/"говно"/повторное недовольство → промпт на РЕДИЗАЙН через $art-direction, НЕ мелкая правка
- [ ] НИКОГДА не исправлять самому — только формулировать промпт
- [ ] Промпт ОДНОЙ СТРОКОЙ (кроме многошаговых планов и redesign-промпта)
- [ ] Указывать конкретный скил если задача им покрывается
- [ ] Указывать конкретные размеры (48px, 375x667) а не "побольше"
- [ ] Дизайн+UX матчить под жанр игры (см. таблицу), не generic
- [ ] Если непонятно — задать ОДИН вопрос: "Это игра или приложение?" (и жанр, если редизайн)
