# $fix-moderation — Разбор замечаний модерации

Пользователь вставляет текст замечаний от модерации Яндекс Игр. Задача — разобрать каждое замечание, классифицировать и исправить.

## Шаги

### 1. Парсинг замечаний
Разбить текст на отдельные замечания. Каждое замечание содержит:
- Описание проблемы
- Ссылку на пункт требований (п. X.X.X)
- Ссылки на скриншоты (опционально)

### 2. Классификация каждого замечания

Определить тип для каждого:

**🔧 КОД** — исправить в `GameIntegration/index.html`:
- Контекстное меню / выделение текста
- Пауза при рекламе
- Звук при рекламе
- GameReady API / LoadingAPI
- GameplayAPI start/stop
- Локализация / автоопределение языка
- Размеры текста / UI overlaps на мобильных
- localStorage → SDK сохранения
- Покупки / consumePurchase
- Опасные паттерны (alert, confirm, prompt)

**📋 КОНСОЛЬ** — исправить в панели управления Яндекс Игр:
- Название игры не совпадает → привести к единому
- Возрастной рейтинг → поставить правильный
- Промо-материалы → заменить скриншоты
- Иконка / обложка → загрузить новые
- Описание игры → переписать
- Категория / теги → исправить

### 3. Для каждого замечания типа КОД

1. Найти проблемное место в коде (Grep + Read)
2. Определить что именно не так
3. Исправить (Edit)
4. Проверить что исправление не сломало другой код

### 4. Для каждого замечания типа КОНСОЛЬ

Выдать чёткую инструкцию:
```
📋 КОНСОЛЬ: {описание}
→ Перейти: Яндекс.Игры → Мои игры → {игра} → Черновик
→ Раздел: {какой раздел}
→ Действие: {что изменить}
```

### 5. После всех исправлений

1. Запустить `$release-ready yandex` — убедиться что код чист (диагностика RED/AMBER/GREEN)
2. Собрать новый ZIP — `node scripts/build-yandex-3zips.mjs` (или `$auto-release yandex` для fix→build loop)

## Карта типичных замечаний

| Пункт | Замечание | Тип | Как исправить |
|-------|-----------|-----|---------------|
| 1.6.2.7 | Контекстное меню / выделение | КОД | `contextmenu` → preventDefault, CSS user-select:none |
| 1.8 | Мелкий текст/иконки | КОД | @media(max-width:768px) увеличить font-size |
| 1.10.1 | Обрезка/выход за экран при ресайзе | КОД | Адаптивная вёрстка: UI привязан к краям/safe-area, не к фикс. координатам. Модерация: вписывает в 16:9 → **ужимает окно на 20% по осям** → проверяет на 1280×1024 (5:4), 1366×768, 1920×1080, 2560×1080 (21:9) и др. Нельзя обрезать кнопки/тексты/шкалы/предупреждения о рекламе. Для больших полей — внутренний слайдер/пан. Probe F (runtime-test) гоняет 6 разрешений автоматически |
| 1.10.3 | Наложение/перекрытие элементов | КОД | Ничего важного не перекрывается. Частый провал: плавающее меню/панель (position:absolute, высокий z-index) висит ПОВЕРХ игрового поля и блокирует клик по клетке под ним (Hexfront: unit-actions над гексами). Фикс: убрать панель с поля, сделать закрываемой, или гарантировать что под ней нет интерактивных клеток. Probe G (runtime-test) ловит persistent UI поверх canvas (WARN) |
| 1.19.1 | Лоадер SDK (IT/IF) | КОД | Актуальный лоадер: `<script async src="/sdk.js" onload="initSDK()">`; debug-панель должна показывать `IT` (init true), не `IF`. SDK подключён ДО YaGames.init() |
| 1.19.2 | GameReady — момент вызова | КОД | LoadingAPI.ready() РОВНО когда игра интерактивна (доступно меню ИЛИ можно играть, вкл. стартовую анимацию). НЕ раньше (нет прогресс-бара/чёрного экрана/троббера) и НЕ на секунды позже. Индикатор зелёный ≤90с. Типичный провал: ready() в init() пока ещё грузится → «слишком рано». **ВАЖНО (parkour):** если `YaGames.init()` запущен АСИНХРОННО («не блокирует игру»), игра становится играбельной ДО того как init дорабатывает → ready() и detectLang срабатывают ПОСЛЕ доступности = реджект. Игра должна ждать init (хотя бы lang+ready) до показа играбельного состояния |
| 1.13 | Покупки не работают / не найдены | КОД+КОНСОЛЬ | Если в игре НЕТ кода покупок (getPayments/getPurchases/purchase) — **убрать покупки из черновика в консоли**. Если покупки заявлены — реализовать рабочий флоў: getPayments() при старте → purchase() по кнопке → onReward → consumePurchase(). Яндекс: «не нашли покупки — уберите из черновика, если их нет» |
| 1.19.3 | Разметка геймплея | КОД | Если используешь GameplayAPI.start/stop — start при начале/возобновлении уровня, stop при паузе/меню/магазине/рекламе/потере фокуса (см. сценарии 1.19.3) |
| 2.7 | Возрастной рейтинг | КОНСОЛЬ | Поменять в настройках черновика |
| 2.14 | Автоопределение языка | КОД | ysdk.environment.i18n.lang на СТАРТЕ (до игрового процесса, не «до первого рендера»); реализовать во ВСЕХ играх даже одноязычных; краткий загрузочный текст на др. языке допустим. **ВАЖНО (parkour):** если init() асинхронный, detectLang отработает ПОСЛЕ того как игра доступна = реджект; определять язык ДО показа играбельного состояния |
| 4.4 | Реклама без действия пользователя | КОД | Interstitial только после клика игрока, не на авто-конце/таймере (gestureDelta<500ms) |
| 4.7 | Пауза при рекламе | КОД | onOpen → gs='paused' + AC.suspend() |
| 4.7 | Звук при рекламе | КОД | onOpen → AC.suspend(), onClose → AC.resume() |
| 1.6.1.3 / 1.6.2.3 | Деформация при ресайзе | КОД | resize-хендлер пересчитывает canvas.width/height по offsetW×DPR + redraw. **Привязать resize не только к window "resize", но и к `orientationchange` + `fullscreenchange`** (или ResizeObserver на контейнере) — иначе на мобильном при повороте/выходе из фулскрина сцена обрезается (1.10.1) или деформируется (1.6.1.3). debugcheck v2.12 ловит это (WARN) |
| 1.6.1.7 | Уведомление о WebGL | КОД | Убрать любой "WebGL not supported/включите WebGL" prompt (debugcheck v2.7) |
| 1.6.1.6 / 1.6.2.5 | Системный плеер (видео И аудио) | КОД | `<video>` без `controls` (либо controlsList+disablePictureInPicture). **Музыка: НЕ `new Audio()`/`<audio loop>`/MediaSession** — они показывают системный плеер (desktop 1.6.2.5) и плеер в шторке уведомлений (Android/iOS 1.6.1.6). Музыку гнать через Web Audio API: fetch→decodeAudioData→AudioBufferSourceNode(loop=true) на том же AudioContext, что и SFX; убрать navigator.mediaSession. debugcheck v2.13 ловит (WARN) |
| 5.11 | Повторяющиеся символы / дубли текста в черновике | КОНСОЛЬ+JSON | Запрещено набивать минимальную длину повторами (пробелы, дефисы, точки) и дублировать текст между полями. seo_description ≠ about ≠ how_to_play, каждое — осмысленный уникальный текст. store-listings валидатор ловит padding (`----`, `....`) и идентичные поля |
| 1.6.1.2 | Клавиатура на поле ввода | КОД | text `<input>` → `.focus()` чтобы открылась моб. клавиатура (v2.7) |
| 1.18 | Ограничение по URL | КОД | Убрать проверки location.host/href/referrer (v2.7) |
| 4.2 | Прогресс после рекламы | КОД | setData/save ПЕРЕД showFullscreenAdv (прогресс переживает reload, v2.7) |
| 8.2.3 | Непереведённый текст при смене языка | КОД | setLang→полный re-render, 0 кириллицы в DOM на non-RU (Probe C) |
| 1.14 | Краш при повороте/жестах | РУЧНАЯ | Прогнать orientationchange + свайпы вживую; runtime-test не ловит все вылеты |
| 1.6.2.2 | Соотношение сторон поля (десктоп) | РУЧНАЯ | Длинная сторона ≤ 2× короткой — проверить в окне визуально |
| 4.3 | Ориентация рекламы | РУЧНАЯ | Ad-блоки в той же ориентации что игра — проверить на устройстве |
| 1.2.2 | Гостевой вход | РУЧНАЯ | Игра играбельна и прогресс идёт без авторизации |
| 3.5 | Чужая интеллектуальная собственность | РУЧНАЯ/КОНСОЛЬ | Чаще в скриншотах store-листинга, не в коде — сверить медиаматериалы |
| 5.1.1 | Промо-материалы | КОНСОЛЬ | Загрузить скриншоты реального геймплея ≥70% |
| 5.1.3 | Название не совпадает | КОНСОЛЬ | Привести к единому во всех полях |
| 5.6 | Иконка = скриншот | КОНСОЛЬ | Иконка/обложка НЕ скриншот из игры |
| 5.12 | Название не уникально | КОНСОЛЬ | Уникальное имя в каталоге для всех языков |
