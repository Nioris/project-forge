# $pixel-art-pipeline — пиксельная графика: PixelLab или своими силами

Выбрал пиксельный стиль (art-direction) → **сначала 🔴 РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ об источнике**,
потом производство. Не выбирать за него: у вариантов разная цена и разное качество.

## 🔴 Вопрос, который задаётся ДО генерации
```
🔴🔴🔴 ТРЕБУЕТСЯ ТВОЁ РЕШЕНИЕ [Ф4 визуал]
Вопрос: чем делаем пиксель-арт?
  А) PixelLab (специализированный сервис, MCP прямо в Claude Code) — платно по подписке.
     Умеет то, чего обычные генераторы не умеют: 8-направленные персонажи, АНИМАЦИИ
     (walk/run/idle), Wang-тайлсеты без швов, изометрические тайлы, стиль по референсу,
     честная прозрачность и точные размеры без «микселей».
  Б) Forge Image Studio (Codex-native ImageGen / GPT Image 2) + наш пост-пайплайн — проще, но анимации и
     8 направлений практически недостижимы, консистентность держится хуже.
  В) Смешанно: персонажи и анимации — PixelLab, фоны и иконки — своя генерация.
Моя рекомендация: <по объёму: нужны анимации или 8 направлений → А или В; статичные
спрайты и иконки → Б>
⏸ Работа ОСТАНОВЛЕНА до ответа.
```
Ответ фиксируется в `wiki/design/brief.md` — переспрашивать в следующих сессиях не надо.

## Вариант А — PixelLab через MCP (официальная интеграция)

### Ключ — в файле, искать не надо
`.pixellab_key` в корне игры или уровнем выше (рядом с optional `.openai_key`, `.elevenlabs_key`).
Прочитай файл и подставь. Нет файла → скажи пользователю: «создай `.pixellab_key` в корне проекта» — и НЕ ищи ключ по конфигам и чужим проектам.
⚠️ Содержимое ключа не выводить в лог, не писать в wiki, не коммитить (в `.gitignore` есть
маска `.*_key`).

### Подключение — ОБЯЗАТЕЛЬНО с областью `user`
```
claude mcp add pixellab https://api.pixellab.ai/mcp -t http \
  -H "Authorization: Bearer <содержимое .pixellab_key>" -s user
```
⚠️ **Флаг `-s user` критичен.** Без него `claude mcp add` привязывает сервер к ТЕКУЩЕЙ ПАПКЕ,
и в остальных играх инструментов не будет — полевой кейс: сервер оказался зарегистрирован в
чужом проекте, а в игре его «нет». С `-s user` сервер виден во всех проектах, включая будущие.

Проверка (обе команды):
```
claude mcp list          → pixellab должен быть в области user
/mcp                     → в сессии: pixellab connected
```
Уже привязан к другому проекту → сперва убрать оттуда, иначе будет двоиться:
```
cd <тот проект> && claude mcp remove pixellab
```
Инструментов нет в сессии, хотя сервер в списке → **перезапусти сессию**: список инструментов
строится на старте.

Инструменты, которые появляются у агента:
| Инструмент | Что делает |
|---|---|
| `create_character(description, n_directions)` | персонаж в 4 или 8 направлениях |
| `animate_character(character_id, animation)` | анимация к существующему персонажу (walk, run, idle…) |
| `create_tileset(lower, upper)` | Wang-тайлсет для бесшовных переходов (например вода→песок) |
| `create_isometric_tile(description, size)` | одиночный изометрический тайл |

Правила использования:
- **сперва один персонаж и утверждение стиля** (библия, Step 4.2), потом остальные —
  у сервиса есть генерация по референсу стиля, ей и держим консистентность;
- `character_id` **сохранять в `wiki/design/pixel-assets.md`**: анимации привязываются к
  персонажу, потеряешь id — придётся генерить заново и платить дважды;
- размеры кадров и число направлений задать ОДИН раз для всей игры и не менять;
- генерация платная → попадает под правило 💸 «дорогие пакетные работы»: сперва один
  элемент, утверждение, потом пачка.

## Вариант Б — Forge Image Studio
Работаем через `$prompt-compiler` → `$image-studio`, затем пост-пайплайн: генерить крупно → уменьшить → переиндексировать
палитру → чистка). Честно предупреди пользователя об ограничениях, которые не обойти:
**анимации и 8 направлений диффузионка не держит** — персонаж «плывёт» между кадрами.
Значит: либо статика, либо анимация кодом (scale/rotate/squash, наш game-feel), либо
2-3 кадра руками.

## Общее для обоих вариантов
- размер кадра кратен 2 (16/32/48/64), одинаков для всех юнитов одного класса;
- палитра — из art-direction, после генерации переиндексировать (16-32 цвета);
- проверка читаемости: посмотреть спрайт **в реальном размере клетки** и в чёрно-белом —
  роды/классы должны различаться силуэтом, а не только цветом;
- прозрачность настоящая (альфа), а не белый фон;
- всё сложенное — прогнать `asset-catalog.mjs` и посмотреть одним взглядом.

## Альтернативы, если PixelLab не подойдёт
`pixel-mcp` (adrianoamaral) — рисование пиксель-арта программно (canvas, px/rect/line,
экспорт PNG). Не генерация, а точное рисование: годится для иконок и UI-элементов,
где нужен контроль каждого пикселя, а не «нарисуй мне персонажа».
