# Решение: граф выполнения дополняет девять фаз, но не заменяет их

**Дата:** 23.08.2026 · **Версия:** v4.68.42

## Ситуация

После введения executable completion contracts завершение фаз стало проверяемым, но adapters всё
ещё местами принимали решение по финальному тексту модели: вопрос означал STOP, оптимистичный ответ
мог выглядеть как completion, а перезапуск терял текущую попытку ремонта. Это особенно опасно для
моделей, которые преждевременно останавливаются или описывают будущую работу вместо выполнения.

## Решение

1. `wiki/phases/phase-N.json` остаётся единственным глобальным состоянием девяти фаз.
2. Ограниченная работа описывается строгой `Task` в одном из пяти режимов: `phase`, `change`,
   `review`, `diagnose`, `release`. Ссылка Task на фазу не имеет права продвигать её.
3. Каждая значимая попытка создаёт типизированный `RunResult` с фиксированным `FailureType`.
4. Декларативный graph переводит Task между agent/verifier/decision/system/terminal nodes.
   Repair и provider retry ограничены тремя попытками.
5. Runtime атомарно хранит состояние в `.forge/runs/<taskId>.json`, исключённом из Git. Переход
   защищён lock-файлом; конфликт не замалчивается последней записью.
6. STOP имеет владельца: `user` ждёт ответ, `agent` возвращается в repair,
   `infrastructure` останавливает выполнение до внешнего изменения.
7. Codex получает уникальный `attemptId` на каждый model turn и доверяет новому RunResult/marker
   только при точном совпадении. Timestamp и анализ вопросительного текста остаются legacy fallback.
8. При завершении фазы authoritative marker с прошедшим contract сохраняется раньше supplemental
   graph result. Один RunResult `completed` никогда не закрывает фазу.

## Почему не отдельный Workflow Graph вместо фаз

Фазы — публичная карта жизненного цикла продукта и стабильный UX для человека. Task graph —
внутренний механизм исполнения, ремонта и продолжения. Сведение их в одну модель снова породило бы
конкурирующие номера шагов и сломало бы совместимость проектов, Dashboard и phase skills.

## Границы текущего слоя

Это foundation runtime, а не визуальный node editor. Scope в Task уже проверяется как безопасная
project-relative декларация, но не считается отдельной системой доступа: реальную защиту пока дают
workspace rules, protected paths и sandbox host'а. Scoped tool enforcement и file leases должны
появиться отдельным последующим решением.

## Последствия

- STOP/repair/resume переживают перезапуск и не зависят от формулировки модели.
- Codex и GigaChat используют один host-neutral контракт, сохраняя собственные способы вызова tools.
- `/status` может показать активную Task, но вычисляет текущую фазу только по phase markers/evidence.
- Повреждённый, чужой или некоррелированный RunResult игнорируется либо становится protocol error,
  а не основанием для продвижения.
