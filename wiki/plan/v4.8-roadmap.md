## 3. `scripts/check-bat-encoding.mjs` — verifier для .bat файлов

**What**: Standalone audit script. Scans `scripts/*.bat` files for non-ASCII characters inside `(` ... `)` blocks (causes cmd.exe parser crash, see [[decisions/004-encoding-rules]] and lesson #20).

**Why**: v4.7.1 had this bug — em-dash inside `if/else (...)`. Fixed manually but no gate against regression. Next person editing .bat files (or a sed replace adding non-ASCII) could re-introduce.

**How**:
```javascript
// Pseudo:
for each .bat file:
  parse line by line, track () nesting depth
  if non-ASCII char found while inside parens:
    report violation with file:line + suggestion
```

**Acceptance**: `node scripts/check-bat-encoding.mjs` returns 0 if all .bat files clean, 1 with helpful violation report otherwise. Add to setup.sh / setup.ps1 validation.

**Lesson source**: Lesson #20 (chcp 65001 ≠ full UTF-8, parser bug).

## 4. `scripts/check-cross-refs.mjs` — automated audit advisor catalog vs filesystem

**What**: Verifier that compares advisor SKILL.md catalog against actual `.claude/skills/` folder contents. Flags missing entries (skills exist but advisor doesn't know) and phantom entries (advisor mentions skills that don't exist).

**Why**: This bug repeated 5+ times. Most recently in v4.7.5: full advisor rewrite accidentally lost 4 skills from catalog (`/convert`, `/convert-all`, `/plan`, `/rustore-publish`). Each time I run a manual grep + re-add. Should be automated.

**How**: Reuse logic from manual checks I've been running:
```python
table_skills = grep advisor SKILL.md for "| name |"
slash_cmds = grep advisor SKILL.md for "/name"
all_skills = ls .claude/skills/
missing = all_skills - (table_skills | slash_cmds)
phantoms = (table_skills | slash_cmds) - all_skills - {wildcards}
```

**Acceptance**: Coverage 80/80 (100%), 0 phantoms, exit 0. Otherwise exit 1 with detailed report. Add to setup.sh validation step.

**Lesson source**: Lesson #14 + 5 occurrences of catalog drift across v4.5.x → v4.7.x.

**Lesson source**: Lesson #26 (architectural vs tactical recognition), Decision 010 (formalization).

## 7. wiki-audit hook tolerance — fix mtime false positives

**What**: Currently `wiki-audit.mjs` does strict mtime comparison. If wiki files mtime is even 1 second behind session log, it blocks `/stop` with "wiki out of sync".

**Why**: Spiral Vigil session showed real example — wiki files were updated, but mtime tracking gave false positive. Claude had to do `touch -d "+5 minutes"` workaround.

**How**: Add ±2 second tolerance в comparison. Or compare to git log (changes since session start, not mtime).

**Acceptance**: No false positives in normal workflow. True positives (wiki actually not updated) still caught.

**Lesson source**: Real Spiral Vigil session bug.

## 8. Visual regression for dashboard

**What**: Headless screenshot (puppeteer) of `dashboard.html` rendered with sample data. Compare against baseline. Flag if pixel diff > threshold.

**Why**: v4.7.4 had z-index regression — added cover image, edit button got hidden. Caught by user, not by automation. With visual regression, would have caught before ship.

**How**:
```javascript
import puppeteer from 'puppeteer';
const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.goto('file:///path/to/dashboard.html');
await page.evaluate(() => { /* seed sample projects to localStorage */ });
const screenshot = await page.screenshot();
// compare with baseline.png — if diff > 100 pixels, flag
```

**Acceptance**: Run before package, fail if regression detected. Baseline image committed to repo.

**Lesson source**: Lesson #23 (z-index conflicts when overlaying new elements).

## 9. Steam validator — handle aliased ESM imports

**What**: Already done in v4.7.7 audit. But pattern (regex needs to handle `import sw from 'steamworks.js'` not just `require('steamworks.js')`) should apply to other validators.

**Why**: Audit пойд by pattern — same regex limitation might exist в:
- `vkplay/validators/iframe-init.mjs`
- `yandex/validators/sdk-init.mjs`
- Other SDK init checks across all 7 platforms with validators

**How**: Extract `detectImportedNames()` helper into `platforms/_shared/_lib/imports.mjs`. Use it in all SDK init validators.

**Acceptance**: All 7 platforms with SDK init validators correctly detect aliased imports (test cases: `import sw from`, `const x = require()`, `import { init } from`).

**Lesson source**: Real audit finding в v4.7.7.

## 10. MCP integration — Forge as MCP server

**What**: Expose Forge skills/agents/hooks via MCP (Model Context Protocol) so other Claude instances (not just Claude Code) can use them.

**Why**: Currently Forge ties into Claude Code via `.claude/` folder. But:
- Claude Desktop with MCP could use Forge as connector
- Web-based Claude could access Forge via remote MCP server
- Forge could be installed once and used across multiple Claude instances

**How**: Create `mcp-server.mjs` that exposes:
- Tools: each skill becomes MCP tool
- Resources: wiki/, skills/, platforms/ as readable resources
- Prompts: orchestrator prompts as MCP prompts

**Acceptance**: User can install Forge MCP server in Claude Desktop, type "use Forge to release my game" without `cf` terminal.

**Status**: Speculative — depends on MCP ecosystem maturity. Defer if other items take priority.

**Lesson source**: User suggestion in earlier conversation.
