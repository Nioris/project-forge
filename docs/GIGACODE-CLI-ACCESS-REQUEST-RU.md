# Запрос доступа к GigaCode CLI для интеграции с Project Forge

**Кому:** support@gitverse.ru  
**Тема:** Запрос доступа к GigaCode CLI для интеграции с Project Forge

Здравствуйте!

Меня зовут Александр Краснокутский. Я 17 лет занимаюсь разработкой игр и программного обеспечения: прошёл путь от программиста и гейм-дизайнера до продюсера, руководителя production и сооснователя игровых студий. Выпущенные при моём участии продукты суммарно набрали более 24 млн скачиваний, я руководил командами до 50+ человек. Последние годы мой основной фокус — AI-first разработка, LLM-агенты, developer tools и автоматизация.

Сейчас я разрабатываю Project Forge — открытый local-first шаблон и оркестратор для создания игр и приложений с помощью ИИ. В текущей студии команда из двух человек уже выпустила более 30 игр и приложений, поэтому Forge развивается на реальном производственном процессе, а не только как экспериментальный прототип. Проект ведётся одновременно на двух площадках:

- GitHub: <https://github.com/Nioris/project-forge>
- GitVerse: <https://gitverse.ru/AlexKras/project-forge>

Примеры игр и приложений, созданных и выпущенных с использованием production-процесса Project Forge:

- RuStore, страница разработчика 3/9 Games: <https://www.rustore.ru/catalog/developer/gzw2swud>
- Яндекс Игры, страница разработчика 3.9 Games: <https://yandex.ru/games/developer/137001>

Project Forge организует разработку в девять последовательных фаз: от анализа идеи и GDD до реализации, тестирования и выпуска платформенных сборок. Для разных ИИ используются отдельные адаптеры, но состояние проекта, решения пользователя, проверки и артефакты остаются в локальном репозитории.

В Forge уже интегрированы и используются в реальной разработке Claude Code и OpenAI Codex. Оба агента работают с одним локальным состоянием проекта, фазами, Git-историей и независимыми verification gates. Теперь мы хотим подключить GigaCode CLI как третий полноценный coding-runtime и проверить его на тех же воспроизводимых задачах — не в отдельной демонстрации, а в действующем производственном конвейере.

Мы уже сделали Forge-owned терминальный адаптер для GigaChat-3-Ultra через API. Он поддерживает работу с файлами и командами, долговременное состояние фаз, обязательные пользовательские решения, web/image-инструменты, локальную диагностику, браузерную проверку, безопасную работу с крупными файлами и доказательное завершение задач. На тестовом проекте GigaChat смог выполнить ограниченную модульную интеграцию новой игровой механики, пройти структурные проверки и браузерный сценарий без ошибок. Одновременно автономный эксперимент по созданию новой игры только из GDD выявил ограничения общей модели при длительной работе с кодом: потерю контекста, текстовую имитацию вызовов инструментов, преждевременные заявления о готовности и повреждение модулей при повторной записи.

Поэтому мы хотим использовать связку из двух продуктов:

- GigaChat-3-Ultra — анализ, GDD, планирование, решения по фазам и ревью;
- GigaCode — непосредственная реализация, исправление и проверка кода в терминальном конвейере Forge.

В публичной документации описан GigaCode CLI, однако на публичной странице установки мы видим в основном IDE-плагины. Расширение Visual Studio Code полезно для ручной работы, но не заменяет отдельный CLI: Forge должен запускать агента из терминала в каталоге проекта, передавать ему задачу, получать код завершения и сохранять машиночитаемый журнал выполнения.

Подскажите, пожалуйста:

1. Можно ли получить доступ к standalone GigaCode CLI для Windows или к эквивалентному headless-интерфейсу?
2. Есть ли программа раннего доступа или возможность выдать доступ для личного open-source проекта?
3. Где находится официальный установщик и как выполняется авторизация CLI?
4. Какие тарифы, квоты и лицензионные ограничения действуют для такого использования?
5. Поддерживаются ли стабильный неинтерактивный запуск, коды возврата, структурированные логи и передача рабочего каталога/задачи через аргументы или stdin?
6. Может ли CLI работать с внешним оркестратором, локальными rules/skills, MCP-серверами и собственными проверяющими скриптами?
7. Допускается ли публично описывать и сравнивать результаты интеграции в Project Forge?

Сейчас Forge уже предусматривает отдельный GigaCode-мост и умеет обнаруживать команды `gigacode`, `gigacode-cli` и `gc-cli`, а также явный путь через переменную `FORGE_GIGACODE_CLI`. На нашей Windows-машине отдельная команда CLI пока отсутствует.

Мы готовы протестировать раннюю сборку, предоставить воспроизводимые сценарии и подробную обратную связь по интеграции GigaCode с многофазной разработкой реальных веб-игр.
