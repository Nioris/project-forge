# Аудит качества Project Forge — 5 сентября 2026

## Итог

Forge уже умеет проводить проекты через фазы, собирать артефакты и проверять доказательства приёмки.
Главный обнаруженный риск — некоторые проверки доказывали наличие отчёта/кадра/токена, а не нужное
поведение игры. Исправления этого аудита укрепляют приёмку, но не заменяют полноценный игровой тест,
художественную оценку и проверку в контейнере конкретной площадки.

База аудита: v4.68.77, commit `364951d`. Исправления подготовлены для выпуска v4.68.78.

## Охват и ограничения

Проверены маршрутизация фаз, completion-контракты, web playtest, визуальные target/capture/review связи,
Godot capture/release зависимости, debug checker, генерация адаптеров, диагностический журнал,
актуальность планов и опубликованных артефактов. Работа разделена на независимые аудиты реализации
и визуальной приёмки с перекрёстной проверкой исправлений.

Из 34 управляемых проектов у семи есть журнал: 509 событий, 74 незакрытые записи. Это исторические
записи, а не 74 доказанных активных дефекта. Игровые исходники и секреты не изменялись; свежий прогон
всех игр, Godot-рендерер, платные AI-запросы, публикация и модерация в этот аудит не входят.

## Что видно по графике

Исторический contact sheet Card Chaos от 29.08 показывает детализированный общий стиль, но боевой
экран перегружен маленькими карточками, счётчиками и инструкциями. Это направление для отдельной
проверки читаемости в реальном размере, не новый формальный verdict: contact sheet уменьшен и не
доказывает актуальную версию. В журнале 04.09 есть свежий конфликт landscape mobile с capture-contract.

Правильная приёмка: утверждённый референс → конкретный экран → настоящий кадр нужной ориентации →
независимая критика с конкретными дефектами → исправление → новая проверка. Нельзя просто поднять
оценки в старом JSON с 6 до 7 или назвать красивый арт доказательством удобного интерфейса.

## Следующие шаги, ещё не реализованы полностью

1. **Покрытие GDD.** Каждый утверждённый feature ID связать с реализацией и игровым сценарием. Наличие
   GDD и базового маршрута ещё не доказывает все механики, баланс, контент и взаимодействия.
2. **Полный Godot-маршрут.** Обязательные победа/поражение/повтор/прогресс/перезапуск с сохранением;
   существующий нативный smoke не покрывает всё это автоматически.
3. **Паритет визуального QA.** Сопоставлять forced-state кадры с экраном, достигнутым обычным игроком.
   Реальный input-тест улучшает доказательство поведения, но сам по себе не сравнивает все арт-кадры.
4. **Безопасная инвалидация.** Не переснимать арт из-за доказанно тестовых файлов; сначала установить
   границы runtime-зависимостей, а не исключать любые каталоги с названием tests/fixtures.
5. **Свежая матрица релизов.** Пересобрать согласованную версию из текущих исходников, проверить Android
   на устройстве, затем собрать реальные внешние подтверждения по выбранным площадкам.

## Проверка и миграция

Регрессии должны включать правильный и сломанный браузерный fixture, подделку/устаревание receipts,
противоречивые viewports, сохранность принятой Phase 4 при диагностике, низкие оценки и ложные PASS
checker. Общий выпуск требует `check-drift`, проверки адаптеров/платформ и ZIP, затем обычного updater.

Для существующей web-игры нужно добавить `forge.web.playtest.json` и read-only наблюдатель состояния,
запустить trusted playtest и только потом перепроверять фазы. Старые отчёты без актуального доказательства
не мигрируются в PASS. Исторические оценки 6/10 остаются историей; новый проход требует исправлений.
Автоматическая синхронизация обновляет Forge, не переписывает игры и их ревью.

Проверено перед упаковкой: browser-contract (10 проверок), phase-completion (включая положительную
приёмку Фаз 3/5 и отказ при изменении receipt), status-model, bump-version, Codex compatibility,
platform completeness, debugcheck fixtures. Общий drift выявил зависание capture teardown; после
его исправления весь phase-completion suite повторно прошёл. Штатный updater повторяет полный drift
на установленном ZIP и проверяет синхронизацию; публикация разрешена только после его успеха.

Навигация по исправлениям: `phase-completion-gate.mjs:412` — playtest proof,
`web-playtest-runner.mjs:130` — реальный браузерный прогон,
`phase-4-visual-evidence.mjs:45` — порог качества,
`platforms/yandex/templates/debugcheck.js:372` — граница обработчика,
`scripts/check-drift.mjs:32` — независимость от рабочей папки.
